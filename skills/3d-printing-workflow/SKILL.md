# 3D printing workflow

This is the general workflow entry point. Retain Support Fins as the specialist procedure rather than copying or replacing its fin-generation and comparison methods. Read the installed `support-fins/SKILL.md` when evaluating fins, angled fin-supported prints, or fins together with BrickLayers. Use the installed storage-awareness skill for capacity checks before slicing, copying or moving packages.

## Recover and prepare the actual project

Identify the current CAD/source revision, printer, nozzle, material inventory, quantities, and existing native slicer project. Reuse compatible named user presets and embed their verified settings snapshots in the project; preserve installed presets and source geometry. For precision parts, maintain units, fit features, scale and explicit clearances. Distinguish source dimensions from assumptions and physical validation.

## Functional fit and tolerance audit

Before releasing mating parts, identify both sides of each actual interface and the intended fit: clearance/sliding, bearing running, keyed retention, threaded fastening, or deliberate press/grip. Record nominal male/female dimensions and the chosen total versus per-side allowance. Audit shaft holes, screw passages and head recesses, nut pockets, rails/tabs, blind sockets and insertion depths, bearing seats, thread flanks and lead-ins. Include the assembled stack and captive/snap components that can become the limiting opening. A matching nominal size is not a clearance fit.

Use explicit local CAD parameters for fit allowances. Choose provisional values from the actual nozzle, line width, orientation, material/process and prior measured fit; do not apply one universal shrinkage percentage or guarantee an unmeasured fit. Material stiffness, hole-printing error, first-layer expansion and support residue can cause binding independently of bulk shrinkage. If measurements are unavailable, use a modest documented candidate and continue the authorized preparation; do not impose separate trial prints when the user has declined them.

Check the entire engagement length, not just an entrance circle or selected edge: transitions, slot intersections, tapers and deeper shoulders can create a narrower throat. Verify before/after dimensions in native CAD where available, exported meshes, embedded slicer objects and critical native toolpath sections. Check the minimum usable aperture across all relevant depths and confirm that the intended positive geometry survives slicing. A profile name, an edited parameter or a single displayed measurement is insufficient.

For selective reprints, treat the retained printed parts as fixed and modify only the authorized replacement's mating surfaces. Preserve reference geometry and revise the matching feature locally rather than scaling the whole part. Keep bearing races, snaps, torque/grip lands, screw alignment, wall thickness and load paths intact; check retention and screw engagement after adding clearance. State which source dimensions are digitally verified and which printed dimensions or physical fits remain unknown. Do not describe a changed female replacement as fixing holes in retained parts.

## Reusable user presets and project overrides

Prefer reusable, plainly named user presets grouped by printer/nozzle, exact material and meaningful process class, such as layer height and wall strategy. Inspect existing compatible presets and reuse them before creating another. Avoid project names, revision tags or unexplained "trial" labels in general-purpose preset names. Preserve installed/system presets and unrelated user defaults; do not overwrite a shared baseline just to tune one plate.

Keep material identity, temperature/cooling, flow limits and hardware compatibility in reusable material/printer baselines. Keep orientation, quantities, packing, supports/blockers, brims and feature-specific changes with the project or object unless they are deliberately part of a reusable process. Choose walls and infill for the load and print-time tradeoff; do not turn a conservative setting from one design into an unexplained universal default.

Embed an exact settings snapshot in each delivered native project for reproducibility without creating a new installed preset for every project. Record the baseline name/version and meaningful deviations separately. When a missing reusable baseline is needed, create one clearly named user preset or importable bundle, rather than repeated near-duplicates; distinguish an embedded snapshot or inspection JSON from an actually installed selectable preset. Apply the user's requested material label accurately and retain calibration/verification status in notes.

Carry the established direct GeekDetour command and editable options into compatible reusable processes, verify its script path and flow limit, and keep heavy audits outside the export hook. Before claiming a new preset is reusable, verify native selection and an export in its intended printer/nozzle context. Preserve source revisions and existing working presets when consolidation is requested, and list any project-specific support or fit settings that must not silently become defaults for unrelated prints.

Choose orientation from the load path, bed contact, support burden and mating-surface quality. Inspect brims, overhangs, external/internal bridges, support contacts, journals, threads, thin features and bed boundaries in actual toolpaths. An enabled support setting or a render is insufficient: check coverage at the relevant layers. Do not assume automatic brims will appear where needed. Preserve structural walls while comparing time/material estimates. Use brims and supports only for identified adhesion risks or unserved overhangs; justify them by actual contact geometry and toolpath coverage. Prefer local enforcers/blockers and modest brim widths over blanket support or brim use. Report support/brim material separately when evaluating savings, and do not claim the physical minimum without adhesion or bridge data.

For angled fin candidates and reported support/model interference, verify that native toolpaths retain the intended positive geometry at critical sections before checking postprocessing. Raw-to-processed path preservation cannot detect geometry already lost by the native slice. Use the Support Fins native model-presence procedure; do not hide missing part material with support blockers.

Use BrickLayers by default for this user's functional parts when compatible with the selected implementation. For editable slicer projects, configure and verify a project-local post-processing script so a fresh GUI export applies BrickLayers automatically. Verify the executable, arguments, path quoting, export behavior, layer synchronization, wall order, extrusion transition and final commanded flow using an actual fresh export. A profile name or script entry alone is not evidence that processing ran. Reuse this user's original direct GeekDetour command from an existing working slicer project when available; keep its multiplier and start-layer flags editable in the native post-processing field. Do not replace it with a project wrapper unless the user requests that change. Keep heavy path/flow audits outside the synchronous slicer export hook. Test actual GUI export completion before release; successful script output alone does not prove the slicer handoff completed. Use exactly one processing pass on a fresh raw slice, never an external pass after an automatic hook. The original script does not itself reject double processing: label final outputs clearly and never feed them back to the processor. If a removed wrapper enforced a material flow cap, preserve that limit through native settings and verify the processed result. Retain raw and final outputs separately.

After user settings change, regenerate the final files from the current saved revision and refresh the root delivery files; older processed files do not reflect new edits. Reopen the final processed G-code in the native viewer and inspect actual staggered wall heights, supports, brims and critical features before delivery. Label cached native previews and estimates as unprocessed. If the slicer cannot support or verify an automatic hook or final-file viewing, disclose the limitation and provide a verified explicit export workflow; do not present an empty-hook project as automatically ready to export or ask the user to discover the missing processing step.

## Deliver files up front

Use one named project folder under the user's chosen Engineering projects location. Put the actual current editable native 3MF build plates and final processed G-code **directly in that project root**, with paired filenames ordered by plate number and identifying parts and material (for example, `PRINT 01 - Base - PET-CF - EDITABLE.3mf` and `PRINT 01 - Base - PET-CF - BRICKLAYERS.gcode`). Do not bury these files in a Print Desk or another delivery subfolder, or substitute shortcuts for drag-and-drop files. Clearly label optional combined plates and which alternatives duplicate parts.

Keep a short `00 - PRINT FILES - START HERE.md` beside them, linking every project/final-file pair and the effective profiles, previews, checks, current CAD and assembly instructions. Keep current editable CAD/assembled exports easy to reach as appropriate. Put model-building scripts, source meshes, tests, slicing work, experiments, archived releases and detailed logs in supporting folders such as `90 - WORKING FILES`. Profiles and previews may be grouped there with direct links from the root guide; label profile files as directly importable or inspection-only. Native projects must embed usable printer, material and process settings.

When reorganizing an existing project, inventory and preserve its files, verify same-volume move targets and hashes, and repair script paths, project-local export hooks and relevant shortcuts. Test the relocated automatic export route. Preserve historical receipts as historical evidence rather than silently rewriting them. Designate the root files as the current user-facing release; nested generation or history copies are not competing print defaults. Record source revisions and hashes, and refresh the root files when settings or geometry change.

Include a per-plate project/final-file mapping, material, piece count, time and grams, plus totals by material. State which estimates are approximate after postprocessing. Clearly mark digital preparation versus physical fit, adhesion, bearing rotation and loaded performance.

## Show the real native project

As part of delivery, open the selected first plate in the user's slicer when UI access is available and the user has authorized desktop interaction. Inspect the live imported settings: an embedded JSON check or CLI reopen does not prove that the GUI selected the intended process profile. Stop a fallback to standard settings and correct the handoff before calling it ready to reslice. Open the final processed G-code separately when needed for its real layer preview. Provide clickable local links even when native opening is unavailable.

Preserve unsaved user work. Open for inspection without sending a printer job. Report any inability to verify native GUI loading directly rather than implying it succeeded.
